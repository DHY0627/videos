## 为什么用网页做视频

画面全部由 `requestAnimationFrame` 里的 JavaScript 逐帧计算，而不是用剪辑软件摆关键帧。

这样做的好处是：**视频变成了一段可以 `git diff` 的代码**。改一句台词、改一个颜色、
改一个场景顺序，都能被版本管理、被审查、被别人复现。想做第二期时，
直接复制上一期的目录，换掉 `script.md` 和场景渲染函数就行。

代价是动画不能用 CSS `@keyframes`（逐帧渲染时会被虚拟时钟打断），
所有补间都得手写在 JS 里。这一点在选择这条路线时就已经接受。

## 目录结构

```
.
├── Ep01_杂食鲸鱼/              某一期的完整源码
│   ├── index.html              入口（双击即可播放）
│   ├── css/style.css           全部样式与配色变量
│   ├── js/
│   │   ├── timeline.js         时长与字幕的唯一真源
│   │   ├── scenes.js           六个场景的逐帧渲染器
│   │   └── outro.js            公用结尾组件（本期的副本）
│   ├── subtitles/subtitles.json  硬字幕数据
│   ├── script.md               分镜脚本（先写它，再写代码）
│   └── README.md               本期的详细说明
└── resource/
    └── outro/                  公用结尾组件母版
        ├── outro.js
        └── outro-preview.html  单独预览页
```

`resource/outro/outro.js` 是母版，各期目录里的 `js/outro.js` 是副本。
这么做是因为逐帧渲染工具会把页面所在目录当作站点根，不允许用 `../` 引用外部文件。

## 怎么跑

**看**：双击 `Ep01_杂食鲸鱼/index.html`。会自动播放，空格暂停，`R` 重播，
`?t=42.5` 跳到指定秒，`?once=1` 只播一次。

**改**：

1. 先改 `script.md` 的分镜表，把时长算出来（规则见那一期 README）；
2. 再同步 `js/timeline.js`、`subtitles/subtitles.json`、`index.html` 的 `data-cf-duration`；
3. 最后才改 `js/scenes.js`。

顺序不能反。先把时长锁死再写动画，否则每改一句台词都要重排全片。

## 导出成片

用任意一个「注入虚拟时钟 + 逐帧截图 + FFmpeg 编码」的工具都行，
本项目用的是 Chromaframe。关键点只有三个：

1. 页面会检测 `window.__cf`，存在时**不自动播放**，交给宿主逐帧拨时间；
2. 所有动画都在 rAF 里读 `performance.now()` 写行内 style，`seek(t)` 是纯函数；
3. 渲染时**把日志重定向到文件**，不要接管道——日志量大时管道会阻塞子进程。

具体命令与三个踩过的坑写在 [Ep01 的 README](Ep01_杂食鲸鱼/README.md) 里。
